# VLA_project

Курсовой проект по мультимодальным и поведенческим моделям.
Цель — научить SO-101 захватывать предмет со стола и переносить его в заданную область или контейнер, используя демонстрации из Isaac Sim и реальной установки.
Исследовательский вопрос — помогают ли симуляционные данные при фиксированном ограниченном количестве реальных демонстраций.

Сейчас готовится рабочее пространство и первые два чекпоинта курса — реальная телеоперация и цифровой двойник сцены. Docker-запуск Sim и WebRTC проверены 2026-11-11. Сборка и калибровка конкретного робота, данные и обученные модели ещё требуют подтверждения.

## Репозиторий и правило веток

Публичный репозиторий проекта — [MakVlad2003/VLA_project](https://github.com/MakVlad2003/VLA_project).

- `main` содержит основную согласованную версию кода, конфигураций и документации.
- Каждый участник работает в ветке с именем своего ника, например `MakVlad2003`.
- Изменения отправляются в личную ветку, затем включаются в `main` через pull request после проверки.
- Перед коммитом проверяются текущая ветка, автор и состав изменений. Данные, веса, кеши и секреты учитываются правилами `.gitignore`.

На mark-pc исходный каталог `~/VLA_project` остаётся на `main`. В общей папке переключение ветки меняет файлы для всех участников. Поэтому для одновременной работы создавайте отдельный worktree для каждого ника.

Однократная подготовка рабочей папки на mark-pc для нового ника выполняется так. Подставь свой ник и персональную Git-подпись.

```bash
cd ~/VLA_project
git fetch origin
NICK=your_github_nick
mkdir -p ~/VLA_worktrees
git worktree add -b "$NICK" "$HOME/VLA_worktrees/$NICK" origin/main
cd "$HOME/VLA_worktrees/$NICK"
ln -s /mnt/jetson-shared/projects/VLA_project storage
git config --worktree user.name "Your Name"
git config --worktree user.email "YOUR_GITHUB_NOREPLY_EMAIL"
git branch --unset-upstream
```

Если твоя ветка уже существует на GitHub, при создании worktree используй её вместо `origin/main`. Для существующей локальной ветки используй `git worktree add <путь> <ник>` без `-b`. `.git` всех worktree связан с основным репозиторием, рабочие файлы у них отдельные. Ссылка storage в каждой рабочей папке ведёт в общее хранилище.

Перед отправкой своих изменений проверь текущую ветку и подпись автора.

```bash
git branch --show-current
git var GIT_AUTHOR_IDENT
git status --short
git diff
# Добавить только файлы своей задачи
git add path/to/changed_file
git commit -m "Describe the change"
git push -u origin "$(git branch --show-current)"
```

Для push понадобится GitHub-доступ участника к репозиторию. Временный deploy key первого опубликования удаляется после этой операции. Все участники используют один Linux-аккаунт, поэтому учитывайте общий Git credential helper и SSH agent при входе в GitHub.

Основной каталог обновляется из согласованного main командой `git pull --ff-only origin main` после проверки локальных изменений. Launcher в текущем контейнере использует основной checkout. Для запуска кода из личного worktree сначала согласуйте с коллегами GPU и перезапуск контейнера с нужным каталогом.

## Запуск симулятора курса

В терминале mark-pc выполни команды ниже. По умолчанию `shmux.sh` запускает контейнер в отдельной tmux-сессии. Повторный запуск показывает текущий контейнер. Работа продолжается после закрытия SSH-терминала.

```bash
cd /home/makarov_vd/VLA_project
./shmux.sh
```

Для запуска нужен исполняемый Bash-скрипт. Используй `./shmux.sh` или `bash shmux.sh`.

| Команда | Действие |
|---|---|
| `./shmux.sh status` | Контейнер, tmux, адрес WebRTC и путь лога |
| `./shmux.sh logs` | Хвост общего лога и новые сообщения, Ctrl+C завершает просмотр |
| `./shmux.sh attach` | Терминал запуска в tmux, Ctrl+B, затем D отсоединяет клиент |
| `./shmux.sh shell` | Bash внутри работающего контейнера |
| `./shmux.sh stop` | Остановка контейнера проекта и его tmux-сессии |
| `./shmux.sh build` | Пересборка образа из закреплённой локальной базы и архива Lab |

Tmux использует отдельный сокет `vla-course`, сессию `isaac`. Контейнер использует host network и GPU, порты TCP 49100 и UDP 47998. Скрипт проверяет NFS и доступность портов перед стартом, а блокировка защищает от одновременного запуска двумя участниками.

В логе ожидаются `VLA_COURSE_RUNTIME_OK` и `Isaac Sim Full Streaming App is loaded.` На проверенном первом запуске полная загрузка заняла около 200 секунд, после прогрева кеша — около 43 секунд. Это наблюдения двух запусков пустой сцены на этой машине.

## Подключение WebRTC

Используй NVIDIA Isaac Sim WebRTC Streaming Client **1.1.5** для Isaac Sim 5.1. На Mac пользователя он установлен в `~/Applications/Isaac Sim WebRTC Streaming Client 1.1.5.app`.

| Поле | Значение |
|---|---|
| Server | `100.98.47.185` |
| Signal | `49100`, если клиент показывает это поле |
| Stream | `47998`, если клиент показывает это поле |
| Resolution | `1920 x 1080 (FHD)` либо меньшая по необходимости |

В клиенте 1.1.5 отдельных полей портов нет, используются значения по умолчанию. После загрузки сервера нажми Connect. Для этого VPN-адреса нужен доступ в ту же VPN-сеть. К одному экземпляру подключается один клиент, участники согласуют использование.

Проверено на Mac 2026-11-11 — видны сетка и интерфейс сцены, мышью открывается File и выбирается World, клавиша W включает инструмент перемещения. Приложение 2.0.0 также было обнаружено на Mac, для этой связки принят проверенный клиент 1.1.5.

После перезапуска сервера при зависшем или пустом окне клиента можно закрыть клиент через меню приложения и открыть снова, затем повторить Connect. На проверке повторное открытие клиента восстановило форму подключения.

[Клиенты для Isaac Sim 5.1](https://docs.isaacsim.omniverse.nvidia.com/5.1.0/installation/download.html)

## Сборка и источник окружения

Dockerfile использует локальные слои базового образа `nvcr.io/nvidia/isaac-lab:2.3.2` с проверкой ID `b746967f76f21f351dae0a910067faad55741fd731ab41bdb4eba585d8e232d3`. Исходники Lab взяты из официального тега v2.3.0, находятся в `storage/runtime/downloads/IsaacLab-v2.3.0.tar.gz`. Проверенная SHA256 равна `bc989537d90452108bfc12423856cebfa98e3a494b892c4d9081a994cc3b063a`.

Установлены пять пакетов Lab из этого тега. Gymnasium закреплён на 1.2.0, Starlette на 0.45.3 согласно setup.py выбранной версии. Остальная базовая среда переиспользуется. Загрузка, импорт Lab и streaming проверены. Полный цикл обучения, необязательные интеграции и связка LeIsaac/LeRobot ещё требуют своих проверок. В исходной базе `pip check` показывал несогласованности необязательных зависимостей, общая чистота всех пакетов пока не установлена.

Сборка использует имеющийся локальный образ через legacy builder Docker. При переносе на другую машину сначала обеспечь доступ к исходному образу и архиву. Попытка чтения манифеста NGC с mark-pc в этой сессии вернула HTTP 403. Скрипт запуска использует уже собранный локальный образ.

[Исходники Lab v2.3.0](https://github.com/isaac-sim/IsaacLab/tree/v2.3.0)

## Восстановление standalone-установки

В `/mnt/jetson-shared/isaacsim/5.1.0/kit` при осмотре было пусто. В скачанном ZIP присутствовали 5722 записи Kit суммарным распакованным размером 266434052 байт. Выполнена выборочная распаковка `kit/*`, встроенный `kit/python/bin/python3 --version` вернул Python 3.11.13. Причина прежней неполной распаковки не установлена. Основной проверенный запуск проекта выполняется через Docker.

В headless-логе присутствуют предупреждения GLFW и deprecated extensions. Приёмка основана на загруженной сцене, видео и управлении в клиенте 1.1.5. Ошибку доступа к OmniCache на первом запуске устранили созданием принадлежащего пользователю каталога до монтирования логов.
