# Данные, сцены и хранилище

Обновлено 2026-11-11. Проектных эпизодов и принятых датасетов пока нет.

## Канонические пути

| Назначение | Из корня проекта |
|---|---|
| Геометрия, текстуры и ресурсы робота | `storage/assets/` |
| USD, снимки версий сцены и связанные материалы | `storage/scenes/` |
| Исходные и экспортированные эпизоды, manifests и splits | `storage/data/` |
| Предобученные модели и checkpoints | `storage/models/` |
| Запуски, логи, видео и результаты оценки | `storage/runs/` |
| Архив исходников Lab и журналы Kit | `storage/runtime/` |

`storage/` — ссылка на `/mnt/jetson-shared/projects/VLA_project`. На Jetson этому соответствует `/mnt/hdd8/mark-pc-shared/projects/VLA_project`. Проект использует выделенный каталог внутри общего 8-ТБ диска. Из контейнера ссылка доступна в `/workspace/VLA_project/storage/`, запись в `data/` проверена. Docker-слои и кеш шейдеров размещены на SSD согласно README.

Диск смонтирован по NFSv3 через локальную сеть. На момент настройки запись с mark-pc сопоставляется пользователю `makarov_vd` на Jetson с UID/GID 2002. На mark-pc UID/GID пользователя — 1001. При изменении прав учитывай это сопоставление.

Перед большими записями проверь NFS, доступное место и доступность Jetson. Новые данные не должны молча попадать на системный раздел при недоступном хранилище. Для нового датасета выбери отдельный путь и зафиксируй его здесь.

## Минимальный контракт эпизода

Перечень задаёт смысл обязательных данных. Точные имена полей определяются после фиксации версии LeRobot.

| Содержимое | Что фиксировать |
|---|---|
| RGB | Камера, кадры, разрешение и обработка |
| Robot state | Имена и порядок суставов, значения и единицы |
| Action | Фактически отправленные команды, представление и единицы |
| Время | Timestamp, частота и синхронизация observation/action |
| Границы | Уникальный episode ID, начало, конец и причина окончания |
| Задача | Task description и текстовая инструкция |
| Происхождение | `sim` или `real`, версия сцены/установки |
| Управление | `teleop` или `planner`, выбранный интерфейс |
| Исход | Успех, неуспех или прерывание и критерий |
| Воспроизводимость | Конфигурация, seed, камеры, версии кода и зависимостей |

Видео и запланированная траектория по отдельности покрывают только часть этого контракта.

## Формат и версии

Оба источника экспортируются в совместимую версию LeRobotDataset. До массового сбора проверить запись, загрузку и просмотр нескольких эпизодов, а также формы признаков, joint order, единицы, FPS, timestamps и action alignment.

Для датасета сохранить источник, путь, версию, объём по эпизодам, способ сбора, правила отбора и manifest. Изменения нормализации или схемы должны быть отражены в версии. Датасеты с разными схемами проходят явное преобразование.

## Отбор и разбиение

- Разделять train/validation/test по целым эпизодам.
- Учитывать связанные повторы и исходные демонстрации при разбиении, чтобы исключить утечку между выборками.
- Зафиксировать real-подмножество для честного сравнения real-only и sim+real.
- Сохранять provenance каждого эпизода и правила исключения повреждённых данных.
- Вести журнал всех попыток отдельно от списка успешных обучающих эпизодов.
- Ориентир курса — около 50 успешных эпизодов на среду после пилота. Фактический объём ещё согласуется.
