# Правила работы

Актуализировано 2026-11-11. Текущие указания пользователя и политики среды имеют приоритет.

## Объём задачи и изменения

- Для небольших правок читай нужные файлы, сохраняй изменения узкими и проверяемыми.
- Для разработки соблюдай существующие интерфейсы, используй простые решения и проверяй изменённое поведение.
- Делегирование существенных независимых задач подчиняется действующим указаниям пользователя и среды.
- Рабочий список задач описывает план. Его наличие само по себе не поручает запуск установки, обучения или оборудования.
- При изменении постановки сверяйся с PRD и исходными требованиями курса.

## Общий аккаунт и совместная работа

- Все участники сейчас используют `makarov_vd`. Перед изменениями проверь занятые файлы, процессы, GPU и порты по задаче.
- Запиши исполнителя и область изменений в TASKS после согласования с командой.
- При появлении Git проверяй status и diff. Добавляй в коммит только относящиеся к задаче файлы.
- Публичный репозиторий — https://github.com/MakVlad2003/VLA_project. Основная ветка — `main`.
- Каждый участник ведёт изменения в ветке под своим ником. Ветка владельца — `MakVlad2003`.
- Код, конфигурации и документация основной версии интегрируются в `main` через pull request после проверки.
- На общем mark-pc checkout `~/VLA_project` остаётся на `main`. Для параллельной работы используются отдельные worktree `~/VLA_worktrees/<ник>`, поскольку переключение ветки общего checkout влияет на всех.
- Для каждого worktree указывайте персональные Git name/email через `git config --worktree`, проверяйте автора перед коммитом. Настройка `extensions.worktreeConfig` включена.
- Перед push проверяйте origin и целевую ветку. Для обычной синхронизации main используйте fast-forward pull. Доступ GitHub оформляется от имени участника.
- Симулятор и GPU остаются общими. При проверке личной ветки сверяйте, какой каталог кода смонтирован в работающий контейнер, и согласуйте его перезапуск.
- Пароли, приватные ключи, токены и авторизационные файлы остаются за пределами документации и Git.
- Для новых участников публичный SSH-ключ добавляется владельцем машины. Фактический вход проверяется с компьютера участника.

## Окружение и вычисления

- Базовая связка курса — Sim 5.1.0, Lab 2.3.0 и Python 3.11. Проверенная совместимость конкретных LeIsaac/LeRobot ещё должна быть зафиксирована.
- Системный Python 3.12 и контейнер Lab 2.3.2 — отдельные обнаруженные окружения. Перед использованием проверь версии и зависимости.
- Выбирайте один согласованный способ установки для рабочего окружения. Контейнерную, standalone- и pip-установку учитывайте отдельно.
- Перед переустановкой исследуй существующую установку и точную причину отказа.
- Согласуй ресурсы длительных заданий. Для длительных удалённых запусков используй tmux или аналог и сохраняй команду наблюдения.
- Запущенный процесс подтверждает только работу процесса. Запуск сцены, запись датасета, обучение и видео принимаются по своим результатам.
- Пакеты, данные и модели загружаются в рамках порученной задачи. Для больших загрузок нужны возобновление, агрегированный прогресс с полосой, объёмом, скоростью и ETA.
- Выбирай прямой путь передачи между серверами. Перед использованием ноутбука как промежуточного хранилища согласуй необходимость.

## Реальный робот

- Перед аппаратной сессией установи, какой экземпляр подключён, роль leader/follower, порт, питание, крепление и состояние калибровки.
- Считывание состояния и запись параметров моторов — разные действия. Изменения ID, калибровок и движения требуют конкретного аппаратного поручения и присутствующего оператора.
- Пользователь запускает критические команды записи при пошаговой настройке. Дай точную команду, физическую схему подключения, ожидаемый результат и точку остановки.
- Руководствуйся инструкцией производителя и выбранной версией LeRobot. Подготовь остановку и свободную рабочую область, проверь движение без предмета.
- Перед переносом политики сопоставь joint order, единицы, пределы, представление действий, камеры и нормализацию.

## Данные и научные выводы

- Контракты записи и разбиение находятся в DATA. Обрабатывай реальные и симуляционные данные с явной меткой происхождения.
- Сохраняй исходы всех попыток в журнале. Учти, что штатный рекордер LeIsaac по описанию курса может сохранять только успешные эпизоды.
- Разделяй выборки по эпизодам. Итоговый тест остаётся отложенным до фиксации модели.
- При оценке пользы sim используй одинаковое реальное подмножество, единый протокол и учёт вычислительных затрат.
- Отделяй измерение, интерпретацию и гипотезу. Указывай число успехов и число попыток.
- Для новых научных и технических утверждений проверяй первичные источники выбранных версий. Навыки критического анализа применяй к соответствующей исследовательской задаче.

## Документы и память

- README отвечает за проверенные команды и работу участников. AGENTS — краткая навигация и контракты агентов.
- PRD отвечает за требования, ARCHITECTURE за структуру и интерфейсы, DESIGN за сцену и эксперимент, DATA за данные, WEIGHTS за модели.
- TASKS содержит статус, исполнителя, блокер и критерий готовности. Задача становится завершённой после указанной проверки.
- MEMORY содержит место остановки, проверенные факты и ссылки. Обновляй после значимых изменений и заменяй устаревшее состояние. Ориентир — до 100 строк.
- COURSE_REQUIREMENTS сохраняет переданный исходный текст. Новые указания преподавателя добавляются отдельным датированным разделом с указанием источника.
- Статусы обозначай явно — проверено, сообщено пользователем, планируется, гипотеза, блокер. Указывай дату для изменчивого состояния.
- При проверках используй временные файлы и убирай собственные тестовые артефакты. Личные резервные копии и новые журналы создавай по необходимости задачи.
