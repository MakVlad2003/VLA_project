# Архитектура и рабочие границы

Обновлено 2026-11-11. Реализованы структура документации, пути хранения и Docker/tmux-запуск Sim. Компоненты сбора и обучения ниже описывают план.

## Поток данных

```text
SO-101 + камера → телеоперация → real-эпизоды ┐
                                           ├→ проверка → LeRobotDataset → обучение → checkpoint
Isaac Sim + сцена → teleop/planner → sim ────┘                                      ↓
                                                  оценка в sim → аппаратная проверка → оценка в real
```

Рекордер сохраняет фактически отправленные команды и синхронизированные наблюдения. Согласование схем выполняется до совместного обучения. Контракты перечислены в DATA.

## Планируемые компоненты

| Компонент | Ответственность | Текущий статус |
|---|---|---|
| Сцена | SO-101, стол, предмет, цель, камера, физика и reset | Предстоит реализовать |
| Управление | Leader/клавиатура/планировщик и интерфейс действий | Способ ещё не выбран |
| Рекордер | Время, наблюдения, команды, эпизоды и исходы | Предстоит выбрать и проверить |
| Подготовка данных | Валидация, экспорт в LeRobot, manifest и splits | Предстоит реализовать |
| Обучение | Конфигурация политики, запуск, checkpoint и логи | Модель ещё не выбрана |
| Оценка | Одинаковый протокол, попытки и метрики sim/real | Протокол ещё не согласован |

LeIsaac рассматривается как интеграция SO-101 с Isaac Lab и записью в LeRobot. Фактические возможности выбранной версии проверяются перед применением. Планировщик требует описания своего робота и логики последовательности захвата.

## Контракт sim/real

Для совместимости должны быть явно согласованы joint order, имена камер и изображений, единицы, система координат, смысл действий, пределы, частота управления и нормализация. Данные среды и конфигурации сохраняются вместе с версиями. Форматы конкретной версии LeRobot проверяются по её API.

## Окружения и проверка

`Dockerfile` создаёт `vla-course:sim5.1.0-lab2.3.0` из локальной базы Lab 2.3.2 с исходниками Lab v2.3.0. `shmux.sh` управляет контейнером `vla-course-sim` через отдельный tmux socket `vla-course` и session `isaac`. Запуск использует host network, GPU и пользовательский UID 1001.

Проект смонтирован в `/workspace/VLA_project`, NFS-каталог дополнительно доступен по исходному абсолютному пути, чтобы ссылка storage работала внутри контейнера. Кеш Kit и home контейнера на SSD, проектные артефакты и runtime-логи на NFS.

`runtime_check.py` исполняется внутри приложения Kit при старте и проверяет версии Sim/Lab/Python, источник импорта Lab, Gymnasium и Starlette. Первая приёмка включила загрузку сцены и WebRTC Client 1.1.5 на Mac, открытие меню, выбор World и инструмент W. Проверены повторный start, остановка и повторный запуск, запись в NFS из Docker.

До рабочего сбора остаётся выбрать LeIsaac/LeRobot, проверить пример Lab/LeIsaac и сцену SO-101, reset, управление и LeRobotDataset. Принятая пустая streaming-сцена подтверждает инфраструктуру запуска.

Standalone Kit восстановлен из имеющегося архива. Его Python запускается. Операционный путь проекта использует контейнер. Команды, источники и ограничения окружения перечислены в README.
