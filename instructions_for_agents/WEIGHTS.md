# Модели и checkpoints

Обновлено 2026-11-11. Модель проекта и предобученные веса ещё не выбраны. Проектные checkpoints отсутствуют.

## Кандидаты из задания

| Кандидат | Назначение | Что проверить |
|---|---|---|
| ACT | Возможное первое решение одной задачи | Наблюдения/действия, память, обучение и инференс |
| SmolVLA | Дообучение VLA с текстовой инструкцией | Checkpoint/revision, память, время шага и задержка |
| Diffusion Policy и другие | Допустимые альтернативы по согласованию | Поддерживаемая реализация и реалистичный бюджет |

Конкретную архитектуру выбирают команда и преподаватель. Наличие 16 ГБ VRAM требует проверки выбранной конфигурации коротким запуском.

## Реестр после выбора

Для каждого checkpoint фиксировать модель, официальный источник, лицензию, revision/commit, локальный путь, объём, конфигурацию и результат проверки загрузки. Для обученной политики добавить dataset versions/splits, предобученные веса, seed, параметры обучения, compute и ссылку на оценку.

Канонический каталог — `storage/models/`. Конфигурации небольшого размера хранятся рядом с кодом после появления обучающего модуля. Крупные веса находятся на общем диске.

## Статусы и воспроизводимость

Различать скачанные веса, успешно загруженную модель, обученный checkpoint и проверенную политику. До инференса сверить камеры, обработку RGB, joint order, единицы действий и нормализацию с записью данных.

Для реального запуска дополнительно нужны согласованные пределы и аппаратная сессия с оператором. Репозиторий модели, датасет и численные результаты должны соответствовать одной зафиксированной конфигурации.
